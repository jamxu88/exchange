## Typical competitor sequence

1. Call [Get User](/rest/user) to confirm identity.
2. Call [Get Markets](/rest/markets) to learn active markets and trading constraints.
3. Call [Get Portfolio](/rest/portfolio) to bootstrap positions and limits.
4. Call [Get Open Orders](/rest/open-orders) and [Get Fills](/rest/fills) after reconnects or if your local state is uncertain.
5. Use [Create Order](/rest/submit-order), [Amend Order](/rest/amend-order), and [Cancel Order](/rest/cancel-order) for order management.

## Request model

- `side` is `BUY` or `SELL`
- `order_type` is `limit` or `market` and defaults to `limit`
- `price`, `quantity`, and `remaining` are integer values
- for market orders, send `price: 0`; the server ignores the field and executes against live opposite-side depth
- competitors can buy from flat, sell from flat, go long, and go short
- risk is enforced with a fixed per-market worst-case net limit of `+/-1000`
- authenticated competitor operations are limited to `100 ops/sec` per API key, and that budget is shared with authenticated WebSocket trading messages
- `open-orders` and `fills` accept an optional `market` query parameter
- REST is the recommended recovery source of truth after reconnects or user-stream uncertainty
