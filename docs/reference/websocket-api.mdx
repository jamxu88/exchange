## Endpoint

```text
wss://exchange.jamesxu.dev/ws
```

## Connection behavior

- the server sends `heartbeat` messages
- market data is sequenced per market
- the current implementation supports one `l3` market subscription per connection
- after authentication, the same socket can carry market data, order actions, and user-specific events

## Competitor message flow

1. Connect to `wss://exchange.jamesxu.dev/ws`
2. [Authenticate](/websocket/authenticate) with your API key if you want to trade or receive user events
3. [Subscribe to an L3 market](/websocket/subscribe-l3)
4. Use [submit order](/websocket/submit-order), [amend order](/websocket/amend-order), and [cancel order](/websocket/cancel-order) as needed
5. Handle [server messages](/websocket/server-messages), especially `snapshot`, `delta`, `fill`, `order_state`, and `resync_required`

## Current limitations

- one market subscription per connection
- no replay endpoint
- no persisted user-event sequence numbers
- no multi-channel market-data model beyond `l3`
