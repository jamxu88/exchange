Use **WebSocket** when you want low latency and a single stream for both the book and your own activity. You still keep **REST** handy for bootstrap and recovery.

The exchange offers two **market-data** channels on the same socket:

- **`l2`** — Public, **aggregated** price levels, derived from the canonical event stream and batched roughly every **100ms** for efficient dashboards.
- **`l3`** — **Authenticated**, **per-order** public book updates from the same canonical stream—useful when your logic needs exact resting-order lifecycle.

```text
wss://exchange.jamesxu.dev/ws
```

## How the connection behaves

- The server sends periodic **`heartbeat`** messages.
- **Market data** is **sequenced per market**; each batch tells you the first and last sequence in the batch.
- **`l2` `delta`** frames can span a range from **`start_sequence`** through **`sequence`**.
- **One** market-data subscription per TCP connection today—open another socket per extra market if you need more.
- **`l2`** does not require auth; **`l3`** does (authenticate first).
- **`l2`** and **`l3`** snapshots and deltas describe the **public** book; your own resting orders are clearest from **`order_state`** and REST.
- After you authenticate, the **same** socket can carry market data, trading messages, and user-scoped events.
- **`submit_order`**, **`cancel_order`**, and **`amend_order`** on the socket count toward the **same** authenticated budget as competitor REST; see [Rate limits](/reference/rate-limits).

## Practical tips

- Keep **REST** in your client for startup and after errors—even if WebSocket is your main path.
- Prefer **one WebSocket per market** if you follow multiple books at full fidelity.
- Use **`l2`** for compact UI-style depth; use **`l3`** when strategy code needs order-level detail.
- Plan for **`market_state`**, **`fill`**, **`order_state`**, **`admin_message`**, and **`resync_required`**—they are part of a complete integration, not edge cases.
- **Book building (`l2`):** apply **`snapshot`**, then each **`delta`**; confirm **`start_sequence`** matches what you expect, then set your cursor to **`sequence`**.
- **Book building (`l3`):** same idea with **`l3_snapshot`** and **`l3_delta`**.
- **`order_state`** is the best live view of **your** resting orders alongside REST [open orders](/rest/open-orders).

## Typical flow

1. Connect to `wss://exchange.jamesxu.dev/ws`.
2. [Authenticate](/websocket/authenticate) if you need **`l3`**, trading, or private events.
3. [Subscribe to L2](/websocket/subscribe-l2) or [Subscribe to L3](/websocket/subscribe-l3).
4. Send [Submit](/websocket/submit-order), [Amend](/websocket/amend-order), or [Cancel](/websocket/cancel-order) as needed.
5. Handle [Server messages](/websocket/server-messages)—especially **`snapshot`**, **`delta`**, **`l3_snapshot`**, **`l3_delta`**, **`market_state`**, **`fill`**, **`order_state`**, and **`resync_required`**.

## Current limitations

- One market-data subscription per connection.
- No historical replay or gap-fill API for market or user streams.
- User events do not carry a durable client-visible sequence you can resume across days—re-bootstrap from REST when reconnecting.
