---
title: "Subscribe L3"
description: "Subscribe to one authenticated raw per-order market-data stream on the socket."
---

Send **`subscribe`** with **`"channel": "l3"`** after **[Authenticate](/websocket/authenticate)** to receive a **per-order** public snapshot, then sequenced **canonical** order events for one market.

**`l3`** is for strategies that need the **exact** public order lifecycle. If you only need aggregated depth, **`l2`** is simpler and does not require auth ([Subscribe L2](/websocket/subscribe-l2)).

<RequestExample>

```json Client Message
{"op":"subscribe","channel":"l3","market":"BTC-USD"}
```

</RequestExample>

<ResponseExample>

```json First Response
{
  "type": "l3_snapshot",
  "channel": "l3",
  "market": "BTC-USD",
  "sequence": 12,

    {
      "order_id": "4d6c28f4-b349-4a4d-8927-8141c36eb6eb",
      "price": 100,
      "remaining": 2,
      "created_at": "2026-03-18T15:28:01.342510Z"
    }
  ],
  "asks": [
    {
      "order_id": "66377526-7b98-485a-8c40-7024e68fa3c5",

    }
  ]
}
```

</ResponseExample>

## Client fields

- `op` must be `subscribe`.
- `channel` must be `l3`.
- `market` is the market you want to subscribe to.

## What happens next

- The server first sends an `l3_snapshot`.
- `bids` and `asks` in that snapshot are raw public orders, sorted by price-time priority.
- After the snapshot, the server sends `l3_delta` messages with contiguous `start_sequence` to `sequence` ranges.
- `l3_delta` events are raw canonical market events:
  - `order_added`
  - `order_updated`
  - `order_removed`
  - `trade`
- If the backend detects a gap or a lagged receiver, it sends `resync_required`.

## Notes

- The current implementation supports one market-data subscription per connection.
- If you need multiple markets, open multiple sockets.
- Use `start_sequence` to validate the first event in each `l3_delta`, then store `sequence` as your new last applied market sequence.
- `l3` is a public order feed. It does not include private trader identity.
- Older clients may still send `last_sequence`; the server ignores it and always starts with a fresh snapshot.
