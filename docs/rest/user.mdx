---
title: "Get User"
api: "GET /api/v1/user"
description: "Fetch the authenticated trader profile associated with your API key."
---

Call this endpoint early—ideally first among authenticated routes—to confirm the server sees the same team identity you expect.

<RequestExample>

```bash Request
curl https://exchange.jamesxu.dev/api/v1/user \
  -H "x-api-key: YOUR_API_KEY"
```

</RequestExample>

<ResponseExample>

```json 200 Response
{
  "trader_id": "c7f8c572-8a50-4dbd-a1e1-9f452774b636",
  "username": "team-alpha",
  "api_key": "exch_c2e2820d1b834d61a596848d36a7ee61",
  "role": "trader",
  "created_at": "2026-03-18T19:14:31.447224Z"
}
```

</ResponseExample>

## Headers

<ParamField header="x-api-key" type="string" required>
  Assigned competitor API key.
</ParamField>

## Response fields

<ResponseField name="trader_id" type="string" required>
  Stable identity used throughout fills, positions, and portfolio responses.
</ResponseField>

<ResponseField name="username" type="string" required>
  Human-readable team label used on the leaderboard and in organizer broadcasts.
</ResponseField>

<ResponseField name="api_key" type="string" required>
  The API key currently associated with the authenticated trader.
</ResponseField>

<ResponseField name="role" type="trader | admin" required>
  `trader` for most competition accounts; `admin` for privileged desk or staff keys (different risk rules).
</ResponseField>

<ResponseField name="created_at" type="string<date-time>" required>
  Trader creation timestamp.
</ResponseField>

## Notes

- If `username` or `role` looks wrong, pause trading and contact organizers.
- Make this the **first** authenticated call in a fresh session.
