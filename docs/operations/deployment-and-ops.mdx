## Deployed shape

- one EC2 instance
- one Rust exchange service
- one local PostgreSQL instance
- one systemd service named `exchange`
- GitHub-backed checkout at `/home/ec2-user/exchange-v2`

## Important paths

- repo: `/home/ec2-user/exchange-v2`
- backend env: `/home/ec2-user/exchange-v2/exchange.env`
- binary: `/home/ec2-user/exchange-v2/exchange/target/release/exchange`
- caddy binary: `/usr/local/bin/caddy`
- caddy config: `/etc/caddy/Caddyfile`

## Update procedure

From your local machine:

```bash
git push origin main
ssh -i "quant-exchange.pem" ec2-user@16.59.150.9 '
  cd ~/exchange-v2 &&
  git pull --ff-only &&
  cd exchange &&
  source "$HOME/.cargo/env" &&
  cargo build --release &&
  sudo systemctl restart exchange &&
  sudo systemctl status exchange --no-pager
'
```

Verify:

```bash
curl https://exchange.jamesxu.dev/health
```

## Current backend env model

The deployed backend should define at least:

- `BIND_ADDR`
- `DATABASE_URL`
- `STORAGE_BACKEND=postgres`
- `ADMIN_API_TOKEN`
- `WS_BROADCAST_BUFFER`
- `PER_USER_REQUESTS_PER_SECOND`
- `POSTGRES_WRITE_BATCH_SIZE`
- `POSTGRES_WRITE_FLUSH_INTERVAL_MS`
- `POSTGRES_WRITE_QUEUE_CAPACITY`
- `POSTGRES_WRITE_RETRY_BACKOFF_MS`

## Operational checks

Service status:

```bash
ssh -i "quant-exchange.pem" ec2-user@16.59.150.9 \
  'sudo systemctl status exchange --no-pager'
```

Logs:

```bash
ssh -i "quant-exchange.pem" ec2-user@16.59.150.9 \
  'sudo journalctl -u exchange -f'
```

## Current public edge

Public endpoint:

- `https://exchange.jamesxu.dev`
- `wss://exchange.jamesxu.dev/ws`

Current host-level shape:

```text
Internet / Cloudflare DNS
        |
       443
        |
      Caddy
        |
  127.0.0.1:8080
        |
    exchange
```

Current reality:

- `exchange.jamesxu.dev` resolves to `16.59.150.9`
- Caddy listens on `80` and `443`
- the exchange process listens on `127.0.0.1:8080`
- Caddy manages the Let's Encrypt certificate for `exchange.jamesxu.dev`
- public `https://exchange.jamesxu.dev/health` is live
- public port `80` still times out, so `http://exchange.jamesxu.dev` does not currently redirect to HTTPS

Current Caddy config:

```caddyfile
exchange.jamesxu.dev {
  reverse_proxy 127.0.0.1:8080
}
```

If Cloudflare proxying is enabled later, it should stay in front of this same `443` origin setup instead of trying to send browser traffic directly to origin port `8080`.

## Current credential debt

GitHub access on the EC2 host is temporarily configured with a stored PAT. Replace it with a deploy key or machine-user SSH key, then revoke the PAT.
